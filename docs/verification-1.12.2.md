# 默认密码库身份与状态修复（1.12.2）

## 根因

1. Gateway未显式配置name时activeName为undefined，但实际文件默认为default.json。listVaults用名称字符串比较，使default库未标为当前库。
2. 显式path与name不同也会出现相同问题；共享roster/model列表存在同类名称比较。
3. 云同步检查要求恰好一个当前库；没有当前标记便提前返回，未继续检查状态/权限，页面只有笼统“暂不可用”。
4. 底部状态将初始化加载、等待输入主密码、创建密码库、读取失败都归到“状态不可用”，无法说明具体状态。

## 修复

- 默认名称归一化；Gateway当前库、列表/共享roster/model列表以实际resolve后的文件路径判断。
- Gateway自身读库与权限路径固定到自己的实际文件，不受另一模型调用的模块级名称覆盖误导。
- 未输入主密码时列表只报告文件身份，不尝试空密码来统计条目，避免无意义的鉴权失败计数。
- 云同步检查不在浏览器猜测第一个或默认库。无当前标记/多个当前标记均明确报身份错误并禁止同步。
- 区分本地检查阶段：检查中、列表读取失败、无当前库、多个当前库、解锁状态读取失败、权限读取失败、换库失效。提示不含原始后台错误或机密内容。
- 锁库观察仍立即撤销草稿；只读/换库/请求过期边界保留；重试重新读本机状态。
- 底部区分检查密码库、等待打开/创建、处理中、已锁定、加载条目、条目读取失败、就绪。表单错误保留在表单旁，底部仅简短状态，避免重复播报。
