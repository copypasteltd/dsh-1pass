# GitHub 推送／同步修复（1.12.1）

## 已复现的根因

1. **空子目录保存成功但通道无法创建**：配置层写入subdir空串，Git层直接交给要求非空的命名空间校验。修复为空/省略统一使用专用1pass目录，绝不写仓库根；明确填写的目录保持不变，清空字段也能真正重置。
2. **默认分支硬编码main**：master/trunk仓库被错误地另建main。修复为读取远端HEAD；空仓库保留其未出生默认分支。异常远端HEAD明确报错，显式分支选项仍显式处理。
3. **失败重试读到“伪远端”**：推送失败留下的本地加密提交被list当成远端快照，阻止首次推送重试。修复list/download读取最新远端ref，重试保留并重用确切本地提交，不重置、不强推；丢失成功回执仅在没有别的远端写入时幂等确认。
4. **通道串用**：点未激活通道卡片时，同一React事件闭包仍读取之前通道。修复为每次操作显式捕获通道及最新状态，确认绑定确切预览令牌。
5. **配置保存与预览互相撤销**：延迟保存即使内容相同也撤销预览；设置加密密码还会撤销正在排队的仓库配置。修复为先等待配置保存，内容相同不失效；普通设置更改只使预览失效，锁库/换库/只读变更才撤销完整授权。
6. **初始状态迟到覆盖表单草稿**：真实异步状态返回把用户新填仓库地址重置为空，使密码框/推送区消失。修复草稿revision保护，迟到状态不能覆盖已编辑表单/通道。
7. **禁用无解释／失败被吞掉**：缺少同步加密密码时按钮灰色但无近邻说明。现在展示缺少哪项及设置密码入口；保留安全白名单错误码并给本地化处理方法，不展示Git stderr/token。
8. **暂时状态失败不可恢复**：增加重试，刷新会重读状态/权限；普通busy不再销毁输入，云端自身busy不回喂不可用状态。锁库与切库仍清除机密草稿；忙碌时也允许刷新锁状态以撤销在途完整条目读取。

## 使用

刷新DSH，确认密码管理页底部v1.12.1。Git配置子目录可留空（默认1pass）。在该通道安全选项填两次相同“同步加密密码”；有历史加密快照时必须使用当时的同步密码。按钮旁会显示尚缺哪项。首次推送先预览后确认；不要强推或随意重新克隆已有积压工作副本。若提示写入被拒绝，检查token对目标私有仓库的Contents读写权限或重新授权；登录成功本身不证明拥有仓库写权限。
