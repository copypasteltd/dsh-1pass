## 原方案与新方案

原 cloud-backup 管理器只把加密库文件单向上传到 GitHub Contents/S3/OSS/R2 并清理旧副本，没有双向同步、共同祖先或冲突裁决。新版新增实际 Git、WebDAV、S3兼容对象存储、Gist 四通道；Git不是GitHub Contents接口。

- 每通道独立配置、鉴权、安全密码、范围、自动同步和目标指纹。
- 推送：预览→确认；预览绑定本机内存/磁盘版本、通道/选择配置及完整远端索引摘要；确认和实际上传再次检查。
- 同步：下载并校验加密快照；在宿主内解密；按条目ID与加密保存的共同祖先做三方比较。无冲突字段可合并；数组/私钥/密码的并发修改不按文本猜测。
- 冲突确认只展示变更标识与遮罩，不把真实密码、TOTP密钥或私钥传给浏览器预览。未确认项保持本机，且不推进同步基准。
- 写入前保留加密回滚副本；同一VaultStore锁内校验实际磁盘、内存与预览，原子写入后发布缓存。另一个CLI在预览前或预览后写入都会拒绝陈旧提交。
- 远端删除本机条目需要人工确认，不因缺失条目自动删除凭据；回滚也拒绝覆盖同步后新增的本机编辑。
- 自动同步：缺省关闭；每通道定时、本地写入去抖和远端轮询；启动/远端轮询只下行，不把启动当作授权上传。首次无基准需要人工确认。真冲突按“询问／本机优先”选项处理，低风险档不会自动应用密码库。
- 保留策略复用参考GFS纯函数，默认最近10个，刚上传项恒保留；清理失败单独告警。Git删除不清除Git历史。
- 稳定本地目录映射使重命名保留通道槽/共同祖先，删除后重新创建不会自动继承旧上传授权。
- 旧单向备份配置保留在本地备份的“旧版云备份（仅迁移）”折叠入口，旧格式不伪装成新同步快照，四通道不自动继承旧目标授权。

## 渠道并发边界

Git执行clone/fetch/merge--ff-only/commit/non-force push。WebDAV与AWS式S3以ETag/条件写保护索引；无ETag的服务明确告警。OSS既有索引更新为前置HEAD复核，不是原子CAS。Gist不伪装成CAS，执行写后验证并明确其未观察并发写入的剩余风险。测试没有访问真实云端或用户账号。

## 安全

AES-256-GCM+scrypt，密码库载荷与共同祖先始终加密，KDF/大小/条目数有界，跨域重定向不携带鉴权。通道密码仅经本机DSH凭据槽写入，配置/报告只返回“已配置”状态。只读、锁库、换库、目标改变、卸载均撤销在途能力并等待受控I/O。新增接口只在GUI中使用，不注册批量密码模型工具。

同步密码与保险库主密码是不同概念：另一台设备需要相同同步解密密码，但可使用自己的本地保险库主密码。不得把密码粘贴在聊天中。
